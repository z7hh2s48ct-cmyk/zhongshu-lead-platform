# 合家美宅客资平台 V1.2 产品需求基线

- 状态：冻结
- 冻结日期：2026-08-06
- 代码基线：`release/v1.0.1`
- 目标分支：`release/v1.2.0`
- 适用对象：产品、业务、后端、H5、管理后台、电销、测试、实施、运维

> 2026-09-13 经业务确认，本文中“有效确认后 3 个工作日观察”的奖励口径已被 [领取48小时自动有效与奖励结算](2026-09-13-领取48小时自动有效与奖励结算.md) 取代。新口径为人工电话确认有效时及时结算；未提前确认的，领取后连续48小时未正式申请退回则自动认定有效并立即结算。草稿不算正式申请。人工提前结算不取消48小时退回权；退回通过时幂等冲回已入账奖励，驳回则保持入账。本文保留原冻结基线便于历史追溯。

## 1. 版本目标

在保留 FastAPI、SQLAlchemy、PostgreSQL/SQLite、原生 H5 与 PC 管理后台架构的前提下，完成“平台手工录入/供应商上传 → 去重 → 待派发池 → 人工派发 → 领取扣分 → 领取后 48 小时内申诉 → 后置电销核验 → 供应商奖励结算”的可执行、可审计闭环。

## 2. 最高优先级冻结规则

1. 正常客资取消前置电话核验；完整性、授权和去重通过后直接进入 `READY_DISPATCH`。
2. 仅接收方提交退回申诉后创建 `RETURN_VERIFY` 电销任务。
3. 退回证据满足“截图至少 1 项 **或** 电话录音至少 1 项”；后端必须按 OR 校验。
4. 退回申诉期为成功领取后连续 **48 小时**，包含周末和节假日，并在领取时固化；供应商奖励观察期仍为有效确认后 **3 个工作日**，两者分别计算。
5. 本期仅人工派发；不实现自动、随机、轮询、权重或抢单。
6. 供应商上传的客资不得派发给供应商自己；该限制不可覆盖。
7. 手机号使用 HMAC-SHA256 指纹去重，默认窗口为硬重复 90 天、奖励重复 180 天、历史疑似 365 天。
8. 正常奖励在其他公司领取后进入 `OBSERVING`；到期无有效申诉才结算。`REVERSED` 仅用于欺诈、系统错误或管理员错误修复。

## 3. 角色与公司能力

- 平台录入员工：新建、编辑草稿、提交平台客资；不能审核供应商、派发或改积分规则。
- 平台运营/审核：供应商资料初审、疑似重复裁决、候选筛选、人工派发、退回初审。
- 电销人员：只处理分配给自己的 `RETURN_VERIFY` 任务，提交事实结论，不能终审。
- 平台管理员：规则、工作日历、服务区域、退回终审、奖励异常冲正与审计。
- 供应商公司：上传并查看本公司客资、奖励状态和流水。
- 接收方公司：领取、跟进并在成功领取后的连续 48 小时内首次提交申诉。

公司能力拆分为：

- `LEAD_SUPPLIER`：允许上传客资。
- `LEAD_RECEIVER`：允许接收客资。

同一公司可同时具备两项能力，但服务层必须硬阻止自供自领。

## 4. 端到端流程

### 4.1 平台录入

草稿 → 必填/格式/授权校验 → 手机号指纹与去重 → `READY_DISPATCH` → 人工派发 → 接收方领取。

### 4.2 供应商上传

H5 上传 → `PENDING_REVIEW` → 平台资料初审与去重 → `READY_DISPATCH` → 人工派发给其他公司 → 他方领取 → 奖励观察。

### 4.3 派发与领取

运营从 `READY_DISPATCH` 发起派发。候选公司按服务区域、接收能力、启用状态、积分资格、自供自领、同接收方历史重复筛选。派发不扣分；领取成功时在同一事务中完成扣分、不可变流水、联系方式解锁、截止时间固化和奖励观察记录创建。

### 4.4 退回申诉

`claimed_at` 起连续 48 小时内：选择四类原因之一、填写说明、上传截图或录音至少一项并完成首次提交 → 创建 `RETURN_VERIFY` → 电销提交结论 → 管理员终审。已按时提交的申请可继续核验和按要求补证，不因平台处理跨过首次提交截止时间而自动失效。

允许原因：

- `EMPTY_NUMBER`
- `OUT_OF_SERVICE_REGION`
- `DUPLICATE_TO_RECEIVER`
- `NON_HOUSING_CONSULTATION`

通过：接收方返分一次、客资回收、供应商奖励取消。驳回：不返分，订单继续；若已过奖励截止则立即结算，否则继续观察。

### 4.5 奖励

其他公司领取 → `OBSERVING` → 观察期内申诉则 `FROZEN` → 无申诉到期 `SETTLED`；申诉通过 `CANCELLED`。

奖励积分：`floor(领取实际扣分 × 奖励比例快照)`，再应用可配置最低值与最高值。默认比例 30%。

## 5. 状态机

### Lead

`DRAFT`、`PENDING_REVIEW`、`READY_DISPATCH`、`DISPATCHED`、`CLAIMED`、`FOLLOWING`、`COMPLETED`、`INVALID`、`DUPLICATE`、`CLOSED`。

### Return

`DRAFT`、`SUBMITTED`、`VERIFYING`、`REVIEWING`、`NEED_MORE_EVIDENCE`、`APPROVED`、`REJECTED`、`EXPIRED`。

### Reward

`NOT_ELIGIBLE`、`WAITING_CLAIM`、`OBSERVING`、`FROZEN`、`SETTLED`、`CANCELLED`、`REVERSED`。

历史 `VERIFYING`、`QUALIFIED`、`PENDING_48H` 等状态只读兼容，不伪造或批量改写历史业务事实。

## 6. 数据与约束

主要新增/调整对象：

- `leads`：来源、提交人、供应商、手机号指纹、去重结论、平台初审状态。
- `company_service_regions`：城市/区县、审核状态和审核人。
- `verification_tasks`：`task_type=RETURN_VERIFY`、退回与派发关联、联系结果、核验结论。
- `return_requests` / `return_evidences`：申诉截止、证据摘要、核验和终审信息。
- `supplier_lead_rewards`：供应商、接收方、扣分与奖励快照、截止时间、规则版本、流水。
- `calendar_days`：日期、是否工作日、节假日、来源和版本。

必要约束：

- 同一客资仅一个有效派发。
- 领取扣分、返分、奖励和冲正均通过幂等键/唯一约束只记一次。
- `supplier_lead_rewards.assignment_id` 唯一。
- 自供自领服务层硬阻止。
- 首次提交退回时截图数 + 录音数 ≥ 1；平台要求补证后，下一轮提交必须包含相对该轮基线的新证据内容。
- 派发单 `appeal_deadline_at = claimed_at + 48 小时`；供应商奖励仅在确认有效后进入观察期并写入独立的 `reward_due_at`。

## 7. 非功能与安全

- 手机号密文存储；去重仅使用 HMAC 指纹；日志和通知不得包含明文手机号。
- 附件存私有对象存储，短时签名访问，校验类型、大小、校验和并记录审计。
- 所有接口在后端执行角色、公司归属和字段级权限校验。
- 积分流水只新增，不编辑、不删除；错误通过反向流水修复。
- 通知失败可重试，不得回滚派发、领取或账务事务。
- 常规列表 P95 ≤ 1.5 秒，详情 P95 ≤ 1 秒；领取核心事务目标 ≤ 500ms（不含通知）。

## 8. 本期明确不做

自动/轮询/权重派单、抢单、在线支付、自动录音、云外呼、AI 审核评分、供应商竞价、复杂 BI、微信小程序、原生 App。

## 9. 验收主线

对应 `RQ-001` 至 `RQ-010`，端到端验收至少覆盖：平台录入直达待派发、供应商初审直达待派发、90 天硬重复、自供自领阻止、领取原子事务、证据 OR、退回 48 小时精确边界及周末/节假日连续计时、申诉冻结奖励、无申诉自动结算、退回通过/驳回、权限隔离和历史兼容。
