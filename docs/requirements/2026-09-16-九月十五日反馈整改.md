## 历史与计时

历史未完成正式退回在迁移时以提交时间回填暂停状态。已完成终审或已发放奖励不因迁移重算财务。没有暂停/恢复记录的既有终审保持原先已经生效的结论。

同一派发的退回申请保留原 ID，驳回后重新申请形成新核验任务。重新申请前的原因、说明、提交/审核时间、审核人、核验任务和证据基线保存在不可变派发事件中；证据及已提交核验不删除。

升级前未保存独立轮次快照的历史任务，不用当前申请文本冒充旧申请。历史详情明确提示缺少独立快照，仅展示该任务提交之前已存在的证据与原核验结论；证据显示和下载采用相同范围。

提前奖励的终止合作提现资格同样检查暂停/延长后的退回窗口，避免原 48 小时已过但退回权仍有效时提前支付。

## 接口变更

- `POST /api/v1/v1.2/admin/leads/{lead_id}/pre-dispatch-verification/requeue`：`{reason}`，返回新任务、原任务 ID 和幂等标记。
- `POST /api/v1/v1.2/returns/{return_id}/correct-region-and-redispatch`：`{province_code, city_code, district_code, reason}`，返回退回详情、原领取返分、更新后地区和幂等标记。
- 派发/退回详情与列表新增 `appeal_paused_at`、`appeal_remaining_seconds`、`appeal_resumed_at`。恢复后 `appeal_deadline_at` 为新截止时间。
- 退回证据详情新增 `uploaded_by`、`uploaded_by_name`；重新申请详情新增 `requires_new_evidence`、`current_round_evidence_count`。
- 地区筛选同时覆盖后台实际使用的 `POST /api/v1/v1.2/reports/leads/search`（`region` 字段）和 `GET /api/v1/v1.2/platform/leads?region=...`。报表和客资列表批量返回 `can_requeue_pre_dispatch` 及最近核验结果。
- 前置核验任务新增 `requires_qualified_verification`，标识重新核验轮次；此类任务非 QUALIFIED 时不能批准入池。
- 退回详情新增 `assignment_release_reason`，用于区分无效关闭与区域更正重新入池。

## 数据迁移与回滚

发布时先在停止业务写入与结算任务的窗口执行 `alembic upgrade 0022_return_clock_pause`，再启动对应代码。迁移仅为未结束正式退回回填暂停计时，不重新扣款或补发历史奖励。

代码可以按提交逆序撤销；数据库回退需单独停写并执行 `alembic downgrade 0021_supply_termination_wallets`。降级会先将暂停/恢复时间保存为派发事件，再删除新增列。不得让旧程序在暂停计时业务尚未核对时继续自动结算。

重新升级会恢复降级快照；若降级期间业务状态、截止时间或业务事件发生变化，则记录 `RETURN_CLOCK_PAUSE_RESTORE_BLOCKED`，须逐条核对后再恢复写入及结算。数据库回滚不是直接撤销 Git 提交，需配合备份和业务停写。
