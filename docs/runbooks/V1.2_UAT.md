# V1.2 用户验收测试（UAT）

## 1. 验收原则

- 使用 staging 或生产等价环境、真实浏览器和真实角色账号；
- 微信场景必须在 iOS 与 Android 微信内置浏览器执行；
- 测试手机号使用经授权的专用数据，不得使用无关真实客户数据；
- 每个用例记录执行人、时间、业务 ID、预期、实际、截图和缺陷编号；
- P0/P1 缺陷未关闭不得进入正式灰度。
- 性能容量验收只允许使用隔离合成租户，不得使用生产客户资料；按 `V1.2_PERFORMANCE_CAPACITY.md` 保留 100/300/500 并发、PostgreSQL、CPU/内存/I/O 和签字证据。

## 2. 角色矩阵

| 角色 | 重点验收 |
|---|---|
| 平台管理员 | 账号、角色、配置、审计、全链路追踪 |
| 平台运营 | 供应初审、候选公司、人工派发、退回终审 |
| 电销人员 | 仅退回后的事实核验、任务归属、手机号权限 |
| 财务人员 | 充值、扣分、返分、奖励、冲正和对账 |
| 加盟商老板/员工 | 微信登录、供应、领取、退回、奖励和消息 |
| 供应商 | 供给能力、上传、初审状态和奖励查看 |

## 3. 核心用例

### UAT-01 微信登录与权限

1. 新用户通过服务号菜单进入；
2. 完成 OAuth 和公司绑定；
3. 已绑定用户再次进入保持会话；
4. 公司停用、邀请失效、绑定其他公司时显示安全状态页；
5. 跨公司转发业务深链返回无权且不展示客资摘要。

验收：Cookie、安全跳转和公司隔离均正确。

### UAT-02 平台手工客资

1. 保存草稿；
2. 补充客户授权和必填信息；
3. 提交并执行去重；
4. CLEAR 客资直接进入待派发池；
5. 重复客资按权限放行或驳回。

验收：不创建前置电销任务，手机号仅按权限展示。

### UAT-03 供应商客资

1. 无有效 `LEAD_SUPPLIER` 能力时禁止上传；
2. 能力批准后上传草稿并提交；
3. 平台初审通过进入 `READY_DISPATCH`；
4. 初审驳回显示原因；
5. 供应商只能查看本公司数据。

### UAT-04 候选与人工派发

1. 过滤停用公司、无接收能力、区域不匹配、积分不足公司；
2. 禁止供应商自供自领；
3. 同接收方历史重复按已发布 365 天规则排除；
4. 人工选择公司并派发；
5. 重复点击或并发派发只产生一个有效派发单。

### UAT-05 领取与积分

1. 领取前仅显示脱敏手机号；
2. 派发只预留、不扣分；
3. 领取事务只扣一次积分并写唯一流水；
4. 领取后所属加盟商解锁手机号；
5. 其他公司及无权角色仍无法读取明文；
6. 固化领取后连续 48 小时的首次退回截止；确认有效后再独立固化 3 个工作日的奖励观察截止。

### UAT-06 退回申诉

分别验证四类原因：空号/停机、超服务区、接收方重复、非建房咨询。

1. 截图单证据可提交；
2. 录音单证据可提交；
3. 无证据拒绝提交；
4. 首次逾期进入 `EXPIRED`；
5. 按时提交后可补充材料；
6. 同一申诉不会创建重复活动核验任务。

### UAT-07 后置电销和终审

1. 申诉提交后创建 `RETURN_VERIFY`；
2. 运营分配给有效电销；
3. 只有任务归属电销在处理阶段读取手机号；
4. 电销提交联系结果和事实结论；
5. 电销不能终审或返分；
6. 管理员通过时返分一次、客资回池、奖励取消；
7. 驳回时恢复领取/跟进、奖励恢复观察；
8. 补证时保持冻结并创建下一轮任务。

### UAT-08 供应奖励

1. 领取时固化奖励比例、上下限、去重窗口和版本；
2. 观察期内有效申诉冻结奖励；
3. 到期无申诉结算一次；
4. 申诉驳回且已过截止时立即结算；
5. 欺诈、系统错误或管理员错误可冲正；
6. 其他原因不能冲正；
7. 冲正关联原流水并保留审计。

### UAT-09 通知与深链

覆盖供应提交/初审、派发、领取、退回、核验、终审、奖励观察/冻结/结算/取消/冲正。

验收：站内消息与 Outbox 幂等；真实微信消息可达；失败重试；深链进入正确页面。

### UAT-10 报表与审计

1. 加盟商仅查看本公司报表；
2. 运营报表不包含财务敏感字段；
3. 财务查看授权积分数据；
4. 按 lead/assignment/return/reward ID 追踪完整链路；
5. 审计快照递归脱敏手机号、Token、Cookie 和密钥。

## 4. 兼容性矩阵

- iOS 当前主流版本 + 微信当前正式版；
- Android 主流品牌至少两台 + 微信当前正式版；
- Windows/macOS Chrome；
- Windows Edge；
- 390×844 移动视口与 1440×900 桌面视口；
- 弱网、请求超时、重复点击、返回导航和会话过期。

## 5. UAT 退出条件

- 核心用例 100% 执行；
- P0/P1 缺陷为 0；
- P2 缺陷有负责人、计划和业务接受意见；
- 积分、返分、奖励对账差异为 0；
- 3–5 家试点加盟商签字；
- 产品、业务、财务、测试、技术共同批准进入灰度。
