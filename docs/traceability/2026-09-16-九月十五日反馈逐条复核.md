## 评审修复闭环

两个独立评审分别覆盖资金/计时/历史/迁移，以及路由/核验/搜索/页面。已修复的实质问题：

- 原轮次被新申请文本、证据覆盖：保存提交、待补证和重新申请快照；无快照旧数据明确提示，按原提交时间限制证据范围。
- 退回、供资终止与积分支出锁冲突：公司业务写锁使用 PostgreSQL `FOR NO KEY UPDATE`，积分账户按固定顺序锁定，既保留业务互斥也兼容积分流水外键检查。对应两种资金竞争测试及供资重核竞争测试通过。锁语义核对 [SQLAlchemy 文档](https://docs.sqlalchemy.org/en/20/core/selectable.html#sqlalchemy.sql.expression.GenerativeSelect.with_for_update) 和 [PostgreSQL 文档](https://www.postgresql.org/docs/current/explicit-locking.html#LOCKING-ROWS)。
- 地区搜索、重新核验按钮最初只接到平台客资 DTO，实际后台使用报表接口：已接通真实入口，并补 HTTP 用例。
- 待开始/历史电销证据、上传信息遗漏：复用预览组件覆盖三种状态并增加行为测试。
- 区域修改按钮在未核验时出现、返分后错误显示已关闭：按后端可执行条件展示，区分区域更正重新入池。
- 重新核验未合格仍能批准入池：在重新核验轮后端拒绝，前端去掉不可执行选项；不改变首轮原有运营判断规则。
- 恢复计时显示固定余量：改为按恢复后的截止时间计算页面剩余时间。
- 预览组件增加只读参数后，直接传给 `Array.map` 导致首份证据不能勾选：改用显式参数，真实单证据表单回归验证通过。
