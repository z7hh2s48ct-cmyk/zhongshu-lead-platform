# 2026-09-11 客资系统问题反馈整改记录

## 实现范围

| 需求 | 本次结果 |
| --- | --- |
| 加盟商上传地址搜索 | 城市、区县增加中文关键词过滤，继续使用现有标准地区树和层级联动。 |
| 展示供资加盟商与实际录入人 | 运营客资列表和详情同时展示两者。 |
| 按供资加盟商、录入人筛选 | 报表查询、导出筛选和运营页统一支持。 |
| 运营页完整手机号 | 运营角色增加受控的 `lead.phone.read`，客资、公海池、初审、派发、核验、退回和处理轨迹优先显示完整号码。 |
| 客户姓名选填 | 加盟商端去除必填标识与前端阻断，空值仍由后端统一归一为“未填写”。 |
| 待运营补充 | 新增待办筛选与“补充并继续处理”入口，在原客资表单上方展示电销核验事实和备注。 |
| 核验详情直接处理 | 退回核验详情可直接分配或改派；电销已提交结论时，运营可在同一详情页执行现有终审动作。 |
| 电销历史提交记录 | 现有“我已提交”队列继续使用，本次未重复开发。 |
| 退回详情的核验原因与证据 | 详情增加核验备注、核验人、结论、申诉说明和证据。 |
| 领取后 48 小时可退回 | 主分支已按 `claimed_at + 48h` 计算申诉截止，本次保留并回归验证。 |
| 加盟商供资数下钻 | 加盟商列表和详情的供资数可点击，自动打开该公司供资客资列表，并可继续进入客资详情。 |
| 供资奖励比例 | 保留现有版本化可配置规则；因未提供新比例，本次不发布新数值。 |
| 无员工的加盟商接收派发 | 有在职员工时仍必须选择员工；无在职员工时自动直派唯一有效负责人，负责人可领取、拒绝并收到唯一通知。 |

## 边界

“运营直接判定无效”使用现有退回终审服务，以保留返分、供资奖励和审计联动。本次没有新增跳过电销核验的旁路接口。

本地自动化可验证业务状态、权限、审计、通知和幂等。部署、真实角色 UAT、微信消息送达和新奖励数值发布不属于本次本地代码实现证据。
