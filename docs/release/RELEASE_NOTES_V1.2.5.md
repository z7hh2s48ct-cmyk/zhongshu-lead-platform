# 合家美宅客资平台 V1.2.5 发布说明

## 2026-09-10 退回与提醒流程整改

- 退回首次提交期限调整为成功领取后连续 48 小时，补齐存量未提交期限迁移与审计回滚记录；
- 已确认有效的客资在 48 小时内仍可申请退回，驳回后恢复原完成状态；
- 补证必须提供相对本轮要求的新证据，证据中文文件名可安全预览；
- 领取、跟进和退回页面补齐截止提示、草稿续办与分页；
- 待领取及首次跟进提醒分别通知实际员工和负责人，并修复消息串单、错误链接和并发消费风险。

V1.2.5 是 V1.2.4 上线后的生产热修复版本，处理 2026 年 9 月 2 日真实业务验收发现的两项阻断：公海池客资无法分配给电销，以及后台 XLSX 导出任务持续失败。本版本不覆盖 V1.2.4 镜像，新增独立版本、迁移和发布证据，便于按提交和镜像摘要回滚。

## 前置电销派发

- 新增 Alembic 数据迁移，在生产库没有已发布 `PRE_DISPATCH` 模板时，自动发布默认“前置电销核验模板”；若运营已发布一个或多个版本，迁移保持原数据不变；
- 默认模板版本会接续现有草稿的最高版本，避免与人工配置发生唯一键冲突；
- 回滚只删除本迁移创建且尚未被核验任务引用的模板。已有任务引用时迁移会拒绝降级，防止历史任务失去模板来源；
- 演示和新建环境的种子数据同步补齐该模板，避免开发测试与迁移后的生产环境继续漂移。

## 后台 XLSX 导出

- 生产日志确认 XLSX 已生成，失败发生在 COS `lead-exports/*` 对象上传阶段，根因是 CAM 或 Bucket Policy 未覆盖真实业务前缀，并非工作簿生成失败；
- 对象存储 `--canary` 从单一 `.canary/zhongshu-readiness/*` 探针扩展为三段验证：基础可达、`evidence/v1.2/*` 证据路径、`lead-exports/*` 导出路径；业务路径使用与导出相同的文件上传、读取和删除链路；
- 任一业务前缀写入、读取或清理失败都会返回非零退出码，使生产预检在更新容器前阻断，而不再出现“健康检查通过、真实导出 AccessDenied”的假绿；
- 运维手册补充最小权限 CAM 策略，包含简单上传、下载、元数据、删除以及大文件分块上传所需动作，并明确 Bucket 必须保持私有。

## 部署与验收边界

1. 先备份 PostgreSQL，并将 COS 子账号权限限定到当前私有 Bucket 的 `.canary/zhongshu-readiness/*`、`evidence/*`、`lead-exports/*`；
2. 使用 V1.2.5 不可变镜像执行数据库迁移，再运行 `python scripts/check_object_storage.py --canary`；
3. 生产运营账号从公海池选择一条符合条件的客资，分配给启用中的电销，确认电销工作台出现对应任务；
4. 生产运营账号提交一次后台 XLSX 导出，确认任务变为“已完成”，下载文件可打开且行数、筛选条件和完整手机号权限符合预期；
5. 上述真实业务闭环、容器健康和日志复核全部通过后，才可标记 V1.2.5 生产可用。代码、自动化、镜像发布和真实 UAT 仍是四个独立状态。
